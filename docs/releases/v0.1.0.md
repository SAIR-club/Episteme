# Episteme v0.1.0：First Real Learning Loop

v0.1.0 是 Episteme 第一个具有完整工程闭环的开发预览版（Developer Preview）。它面向开发者和研究者，不是面向普通用户的稳定版本。

## 这一版做到了什么

Episteme 关注的不是生成更多答案，而是让理解过程能够被记录、验证、复用与持续修正。

v0.1.0 第一次把下面这个闭环完整实现：

```text
Agent A 提交带原文证据的候选理解
  → Episteme 校验每一条引用，并保存来源
  → 学习者在 Workspace 中审阅：接受、修改或驳回
  → 只有学习者接受的内容进入理解图谱
  → Agent B 在另一次会话中，通过 recall 取回已确认的理解
```

需要说清楚两点：

1. 这个闭环目前只由自动化测试证明。测试使用脚本化的 MCP 客户端，还没有真实的 Claude Code Host 和真实学习者走通过。
2. 图谱记录的是学习者认可的、当时对自身理解的描述。它不能证明学习者掌握了相关知识。`stated` 只表示被引用的话出自学习者之口，学习者的确认也不等于掌握。

### 已实现，但尚未在真实 Host 上验证

- **与 Claude Code 的连接**：Claude Code 使用哪个 MCP 协议版本，能否与本 Service 的 Streamable HTTP 正常握手，尚未验证。
- **Agent 身份**：如果 Host 走 2025 版的无状态通道，请求不带客户端信息，提议者会被记为 `actor_agent_unidentified`。
- **真实模型的引用质量**：模型能否逐字复制原文、能否正确区分 `stated` 与 `inferred`、引用被拒绝的比例，都还不知道。
- **调用时机**：没有插件和 skill，Host 是否会在合适的时候调用 `recall` 和 `distill`，取决于提示词。
- **审阅成本**：学习者审阅一次学习对话产生的候选需要多少时间和精力，尚无数据。
- **不同 Host 之间的兼容性**：Cursor、Codex 等其他 Host 均未验证。

### 尚未实现

- Claude Code 插件、skill 与 `/episteme` 命令。
- stdio 适配层（目前只支持 Streamable HTTP）。
- 审阅接口的身份与权限控制（ADR 0012，[#17](https://github.com/SAIR-club/Episteme/issues/17)，尚未接受）。
- Workspace 的审阅中心、理解图谱视图与理解时间线。
- 对话存储与对话树；导入 Claude Code 会话记录。
- 按作用域限制 recall；静态加密。
- 会话日志。

## 已知限制与安全说明

1. **Host 辅助蒸馏已实现，但尚未完成真实 Claude Code 试用。**
2. **人工审阅流程已实现，但 REST 审阅接口没有完整的身份授权保护。** 任何能访问本机端口的进程，包括带有 Shell 权限的 Agent，都可以调用 `/api/v1/suggestions/decide`，从而确认自己提出的建议。本地 token 也无法可靠隔离以同一系统用户运行的 Agent。只在自己的电脑上、配合自己信任的 Agent 使用。
3. **Workspace 尚未展示 `basis` 和说话人。** 数据已经在 `/api/v1/suggestions` 中返回，但审阅页面不显示，学习者在页面上分不清一条候选是自己的原话还是 Agent 的推断（[#26](https://github.com/SAIR-club/Episteme/issues/26)）。
4. **检索质量受确定性 embedding 限制。** 默认适配器是测试替身，提问用词与记录相差很大时，可能取不回已存的理解。
5. **`not_pending` 不等于已驳回。** 重试回执中的 `not_pending` 只表示"确实入过队，已不在队列中，图谱里没有由它提交的内容"。驳回操作本身不留记录（[#25](https://github.com/SAIR-club/Episteme/issues/25)）。
6. **数据以明文保存在本地，不适合直接开放到公网。** 图谱、草稿与原始材料都是本地明文 JSONL 文件，既没有加密，也没有身份验证。Service 只监听回环地址，不要把它暴露到网络上。
7. **不承诺跨 Agent Host 的兼容性。** 自动化测试使用的是脚本化客户端，任何具体 Host 的实际兼容性都未经验证。

## 技术债

- [#23](https://github.com/SAIR-club/Episteme/issues/23)：Agent 可以通过 `propose` 提议 `conflict: resolved` 或 `none`；读取逻辑把 `resolved` 也当作冲突处理。
- [#25](https://github.com/SAIR-club/Episteme/issues/25)：`landing` 记录会随带 `submissionId` 的提交持续累积，将来若要清理，必须保留幂等重试、崩溃恢复和 `not_pending` 的语义。
- 路线图中的加固事项：接受论断时的整体预检、"修改"可以改变哪些字段、草稿存储的端口抽象、拆分 `LearnSession`、锁文件对 pid 复用的判断。见 [roadmap](../roadmap/README.md#hardening-backlog)。

## 数据格式

升级到本版无需迁移数据，旧文件可以照常读取。

| 文件                        | 内容                                     | 格式版本       |
| --------------------------- | ---------------------------------------- | -------------- |
| `<graph>`                   | 节点、边与状态事件，理解的唯一来源       | 不变           |
| `<graph>.suggestions.jsonl` | 待审草稿、决策预写记录、提交落地记录     | 3（可读 1、2） |
| `<graph>.sources.jsonl`     | 被蒸馏的原始材料（规范化文本）与提交记录 | 2（可读 1）    |
| `<graph>.lock`              | 单一持有者锁                             | —              |

默认图谱是 `~/.episteme/learn.jsonl`。用于自己学习时，建议在仓库之外单独指定图谱并从空图谱开始：

```bash
pnpm serve --graph "$HOME/.episteme/my-topic.jsonl" --blank
```

## 后续方向

这些是将来的方向，不是 v0.1.0 之后马上要做的开发任务。

- **真实学习验证**：接入 Claude Code，进行两次学习会话，观察引用质量、理解是否被复用，以及人工审阅的成本。
- **安全与可用性**：审阅权限（ADR 0012）、Workspace 显示来源与 `basis`、隐私保护（按作用域限制 recall、静态加密）。
- **研究与社区**：认知状态建模、理解如何演化、学习效果评估、多 Host 兼容，以及开源协作。

v0.1.0 之后，项目进入暂时维护状态。恢复开发时的第一步，见[开发状态](../development-status.md)。
